# Africa Delivery — Architecture Canvas (проект)

| Блок | Содержание |
|---|---|
| **1. Ценностное обоснование** | Покупателям — доступные товары/надёжное получение; продавцам — спрос/своевременная выручка; бизнесу — оборот/доверие/устойчивая экономика заказа. А2; А7 |
| **2. Ключевые заинтересованные стороны** | Покупатели/продавцы — покупки/выплаты; поддержка — операции; CEO/инвестор — объём релиза; CFO — бюджет; CTO/архитектор — эксплуатация; юристы/регуляторы — данные. Местной команды нет. [Полномочия](stakeholder-matrix.md). А1–А3; А5–А6 |
| **3. Ключевые функции** | Принять товары; показать каталог; оформить заказ; подтвердить оплату; передать доставку; показать статус; уведомить о результате; сверить выплату; показать продажи. А1; А4; А8 |
| **4. Требования к качеству** | Цели: доступность 99,99% без деградации; RPO=0; первый товар <2 с. Границы/профиль/сценарий отказа неизвестны. Предложения: 0 дублей заказов/списаний при повторе; проверка развёртывания у другого провайдера. А1; А2, с. 3; А5, с. 1–2 |
| **5. Деловой контекст** | Внешние: покупатели/продавцы, PSP, логистика, связь, магазины приложений, регуляторы. Каналы: приложение/WhatsApp/SMS/USSD. MVP NG/KE: 5 000 SKU/100 продавцов, покупательский маршрут. ЮАР/B2B/аналитика продавца — вне MVP. Перевозку/платёж исполняют партнёры. А2–А3; А7–А8; контекст кейса |
| **6. Ключевые решения** | Зафиксированы: 15.10.2026; ≤5 000 USD/мес. первые полгода; ≤6 контракторов; без нового найма/годовых предоплат; >500 USD/мес. согласует CFO. Токены/полноценный бэк-офис отложены. Стек/разработка–покупка не утверждены. А1, с. 3; А6, с. 1; А7 |
| **7. Составные части** | **Приложение:** покупки/статусы. **Каталог:** товары/остатки. **Заказы:** оформление/доставка. **Расчёты:** оплата/сверка/выплаты/возвраты. **Уведомления:** отправка/повтор. **Управление:** продавцы/модерация/споры/аналитика. **Хранилища:** данные/история. Логические зоны ответственности. А4; А8 |
| **8. Технологии** | Greenfield. Go/PostgreSQL, REST, контейнеры — кандидаты. Внешние API: M-Pesa/Flutterwave, Sendbox/Sendy, WhatsApp Business API. Oracle/Kubernetes/Istio/Kafka/мультиоблако — требования CTO; экономика не согласована. Альтернативы: готовая marketplace-платформа; стек CTO с дополнительными ресурсами. А3; А5–А6; А8 |

## 9. Риски и недостающая информация

| Риск → мера управления | Отсутствующее значение / вопрос → значение для архитектуры | У кого уточнить | Метрика контроля |
|---|---|---|---|
| Перегрузка/простой → нагрузочные/аварийные проверки. А5 | Пик запросов, профиль/процентиль, границы SLO/RPO? → мощности/резервирование | CTO, инвестор | Ошибки; p95 задержки; доступность; потерянные записи |
| Нарушение правил обработки → локальные контуры. А3; А7 | Какие данные/копии/передачи разрешены? → размещение/хранение | Юрист, CEO | Доля юридически подтверждённых потоков |
| Срыв выплат → договоры/сверка. А3; А6–А7 | Сроки расчётов PSP/резерв возвратов? → модель выплат | CFO, CEO | Задержка выплат; комиссия <2,5% GMV |
| Срыв обещаний → ограничение объёма/проверка готовности. А1–А2 | Зоны/SLA, исполнители, статус публикации к 01.10? → объём/интеграции | CEO, маркетинг, CFO | Просроченные доставки; готовые сценарии, % |

## Assumptions

- NG/KE — Нигерия/Кения; PSP — платёжный провайдер. Обещания/SLO меняет инвестор; модерация/возвраты/сверка нужны операционно. А1; А4.
- До уточнения А3 данные/логи/копии не экспортируем: предосторожность, не юридический допуск. Программа CNCF не определена. А3; А5.
- Узкий MVP, подсистемы, стек и новые пороги метрик не утверждены; комиссия задана А6.

**А1–А8:** транскрипт; маркетинг; юристы; функции; CTO; CFO; инвестор; схема. [Вопросы](open-questions.md), [противоречия](contradictions.md).
