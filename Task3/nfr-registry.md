# Реестр нефункциональных требований

**Статус: предложено для пилота Нигерии и Кении.**

Нефункциональные требования описывают качество работы: скорость, надёжность, безопасность и возможность эксплуатации. ID нужен для связи с испытаниями и инцидентами. Значения считаются отдельно по каждой стране.

**SLI** — измеряемый результат; **SLO** — цель команды; **SLA** — согласованное обязательство. **P99** означает, что 99% запросов укладываются в указанное время. **RTO** — время восстановления; **RPO** — допустимая давность восстановленных данных. Подробные определения и ссылки на исходные документы — в [справочнике Task3](reference-guide.md).

## Что означает Cloud Native здесь

Требования NFR-12 и NFR-14–19 покрывают устойчивость, безопасность, наблюдаемость, переносимость, автоматизацию и масштабирование. Контейнеры и описание инфраструктуры полезны уже в пилоте. Kubernetes, Kafka и service mesh не являются самостоятельными требованиями к качеству.

Определение Cloud Native и программа сертификации — разные вещи. [CNCF Certified Kubernetes](https://www.cncf.io/training/certification/software-conformance/) проверяет совместимость Kubernetes. CTO должен назвать программу и критерии, по которым предполагается проверять именно Africa Delivery. До этого формальная «сертификация платформы» остаётся открытым вопросом.

## Assumptions

- Нагрузка NFR-08 предложена для испытаний; число регистраций из письма CTO не позволяет вычислить запросы в секунду. CTO и CEO уточняют ожидаемые пики до утверждения мощности.
- Для NFR-07: Android с 2 ГБ RAM; загрузка 1,6 Мбит/с, отправка 0,7 Мбит/с, задержка сети 200 мс, потери пакетов 1%. Это модель испытания, которую нужно проверить на местных устройствах.
- Серверные P99 не включают время отсутствия связи у покупателя. Отдельная мобильная проверка NFR-07 включает сеть.
- RPO=0 относится к одиночному отказу с исправным синхронным резервом. При потере площадки действует NFR-10; цель не маскирует остановку сомнительных платежей.
- Для доставки сообщений предполагаются квитанции каналов. Если канал их не даёт, NFR-05 по нему не подтверждён: нельзя заменить доставку приёмом.
- Новые числовые значения и пороги — предложения архитектора. Основания: [Task2: Architecture Vision, раздел 3 «Данные, переносимость и качество»](../Task2/architecture-vision.md#3-данные-переносимость-и-качество) и требования текущего задания; утверждают CTO, CEO, CFO и инвестор в пределах своих полномочий.
