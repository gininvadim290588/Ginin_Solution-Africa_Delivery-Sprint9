# Сценарии проверки качества

Сценарий описывает ситуацию, действие системы и измеримый результат. У каждого ровно шесть полей: кто вызвал ситуацию, что произошло, условия, затронутая часть, ответ системы, мера ответа. Так команда может превратить требование в испытание.

## QAS-01 — остановилась одна копия приложения

Основание: [NFR-01/02 — доступность каталога и собственной оплаты](nfr-registry.md); [Task2, Architecture Vision, раздел 2 «Устройство системы и ответственность»](../Task2/architecture-vision.md#2-устройство-системы-и-ответственность).

| Поле | Содержание |
|---|---|
| Источник воздействия | Отказ сервера приложения |
| Воздействие | Одна из двух копий перестала отвечать |
| Условия | Рабочая нагрузка из NFR-08; БД и вторая копия исправны |
| Затронутая часть | Публичный вход и основное приложение |
| Ответ системы | Перестать направлять запросы на отказавшую копию; продолжить работу здоровой; вызвать дежурного |
| Мера ответа | Переключение ≤1 мин, обнаружение ≤2 мин; подтверждённые заказы не потеряны; фактические ошибки включены в SLO |

## QAS-02 — проверяем P99 под нагрузкой

Основание: [NFR-06 — скорость серверного ответа](nfr-registry.md); [артефакт 2, с. 3: мгновенное приложение](reference-guide.md#исходные-письма).

| Поле | Содержание |
|---|---|
| Источник воздействия | Покупатели и генератор тестовой нагрузки |
| Воздействие | Одновременно читаются товары, создаются платёжные заявки и читаются их статусы |
| Условия | Обычная нагрузка NFR-08 в течение 30 мин; тёплый и холодный кеш проверяются отдельно |
| Затронутая часть | Публичный вход, каталог и собственный платёжный API |
| Ответ системы | Корректно ответить; платёжную заявку подтвердить только после записи в БД |
| Мера ответа | P99 каталога ≤1 с, приёма оплаты ≤1,5 с; ≥99% всех учитываемых запросов одновременно успешны и укладываются в соответствующий срок |

## QAS-03 — рекламный пик и добавление мощности

Основание: [NFR-08/19 — нагрузка и масштабирование](nfr-registry.md); [артефакт 5, с. 1: масштаб запуска](reference-guide.md#исходные-письма).

| Поле | Содержание |
|---|---|
| Источник воздействия | Рекламная кампания |
| Воздействие | Поток на страну вырос до 200 запросов/с каталога, 10 запросов/с оплаты и 20 событий/с уведомлений |
| Условия | Обычная нагрузка 30 мин; под ней две копии увеличиваются до четырёх; после готовности четырёх копий — пик 5 мин |
| Затронутая часть | Приложение, БД и фоновая отправка сообщений |
| Ответ системы | Добавить копии приложения; не терять сеансы; сохранить события; ограничить ресурсы каждой интеграции |
| Мера ответа | Четыре копии готовы ≤10 мин от команды масштабирования; пиковый тест проходит при заранее подготовленной мощности; сохраняются P99 NFR-06 и цели передачи сообщений; повторных финансовых действий 0 |

## QAS-04 — отказ основного узла БД

Основание: [NFR-09/11 — восстановление и финансовая целостность](nfr-registry.md); [стратегия доступности: одиночный отказ](availability-strategy.md#как-восстанавливаемся).

| Поле | Содержание |
|---|---|
| Источник воздействия | Отказ узла или сети БД |
| Воздействие | Основной узел PostgreSQL перестал отвечать |
| Условия | Синхронный резерв подтвердил все ранее подтверждённые записи; прежний узел можно надёжно изолировать |
| Затронутая часть | БД заказов и расчётов |
| Ответ системы | Остановить записи, изолировать прежний узел, перевести резерв в основной, проверить учёт и возобновить безопасную работу |
| Мера ответа | RTO ≤5 мин от отказа; RPO=0 подтверждённых записей; одновременно пишущих основных узлов не более одного |

## QAS-05 — потеря всей площадки

Основание: [NFR-10 — восстановление при потере площадки](nfr-registry.md); [Task2, Architecture Vision, раздел 3 «Данные, переносимость и качество»](../Task2/architecture-vision.md#3-данные-переносимость-и-качество).

| Поле | Содержание |
|---|---|
| Источник воздействия | Отключение дата-центра |
| Воздействие | Недоступны приложение и БД основной площадки |
| Условия | Есть подготовленная разрешённая площадка, доступные ключи и независимая копия; условия объёма и сети раскрыты в стратегии доступности |
| Затронутая часть | Развёртывание одной страны, каталог, заказы и платёжный учёт |
| Ответ системы | Изолировать старую площадку, восстановить данные, переключить вход, показать достоверный доступный статус; сомнительные финансовые действия оставить остановленными до сверки |
| Мера ответа | Каталог/чтение статуса восстановлены ≤60 мин от отказа; точка данных не старше 15 мин; сверка затронутых оплат ≤24 ч; ограничения оплаты учитываются в полном SLI |

## QAS-06 — PSP не ответил после возможного списания

Основание: [NFR-03/12 — итог оплаты и изоляция партнёра](nfr-registry.md); [контракт оплаты](slo/payments.md).

| Поле | Содержание |
|---|---|
| Источник воздействия | M-Pesa или Flutterwave |
| Воздействие | Вызов закончился тайм-аутом, но партнёр мог уже списать деньги |
| Условия | Покупатель повторяет действие; сеть партнёра нестабильна |
| Затронутая часть | Платёжная интеграция, статус заказа |
| Ответ системы | Сохранить прежний номер операции; показать ожидание подтверждения; проверять статус с паузами; временно прервать массовые неисправные вызовы |
| Мера ответа | Один вызов ограничен 5 с; повторного списания 0; неизвестный итог после 300 с отмечен как нарушение срока и передан оператору; каталог сохраняет NFR-01/06 |

## QAS-07 — SMS-шлюз отказал

Основание: [NFR-04/05/12 — передача, доставка и изоляция](nfr-registry.md); [контракт уведомлений](slo/notifications.md).

| Поле | Содержание |
|---|---|
| Источник воздействия | Канал SMS |
| Воздействие | Шлюз не принимает сообщения либо не возвращает квитанции |
| Условия | Отправляются сообщения о заказах; запасной WhatsApp-канал разрешён и доступен |
| Затронутая часть | Фоновая отправка и очередь событий |
| Ответ системы | Сохранить событие; ограниченно повторить отправку; использовать допустимый запасной канал с тем же кодом; назначить задачу оператору |
| Мера ответа | Нарушение передачи фиксируется после 60 с, доставки — после 300 с; событие не потеряно; повтор не создаёт новый код; при отказе любого канала каталог остаётся работоспособным |

## QAS-08 — повторное сообщение об оплате

Основание: [NFR-11 — ноль повторных финансовых действий](nfr-registry.md); [Task2, Architecture Vision, раздел 2: повтор запроса и учёт](../Task2/architecture-vision.md#2-устройство-системы-и-ответственность).

| Поле | Содержание |
|---|---|
| Источник воздействия | Платёжный партнёр |
| Воздействие | Приходят 10 000 повторных и переставленных сообщений; часть имеет неверную подпись |
| Условия | Операция уже записана; обработчик может перезапуститься между записью и ответом |
| Затронутая часть | Приём сообщений PSP и финансовый учёт |
| Ответ системы | Проверить подпись и номер; повторно подтвердить приём без повторного финансового действия; отклонить подделку |
| Мера ответа | Повторных списаний, выплат и выдач 0; неподписанных подтверждений оплаты 0; сумма и история совпадают с PSP |

## QAS-09 — блокировка товара и устаревший кеш

Основание: [NFR-13 — актуальность копий](nfr-registry.md); [ADR-002: удаление устаревших копий](adr-002-caching-strategy.md#как-удаляем-устаревшее).

| Поле | Содержание |
|---|---|
| Источник воздействия | Оператор модерации |
| Воздействие | Товар заблокирован, но копии карточки есть на серверах и телефоне |
| Условия | Проверяются все копии приложения и телефон с доступной сетью; отдельный телефон отключён |
| Затронутая часть | Каталог, версии модерации, серверный и мобильный кеш |
| Ответ системы | Удалить/обновить копии; перед заказом прочитать текущую БД; после восстановления связи проверить локальный каталог |
| Мера ответа | В онлайн-каталоге блокировка видна ≤60 с; при отсутствии подтверждения версии >30 с сервер прекращает показ; заказ заблокированного товара невозможен; офлайн-копия помечена устаревшей и удаляется после связи |

## Assumptions

Предоставленное «Приложение В.pdf» содержит карту размещения данных, а не шаблон QAS. Поэтому используется стандартная форма SEI из шести полей, прямо указанных в текущем задании; [методика и ссылка](reference-guide.md#методики).

Нагрузочные числа — испытательный профиль, а не прогноз спроса. Резервирование, договоры и проверки ещё не реализованы. Условия RTO/RPO раскрыты в [стратегии доступности, Assumptions](availability-strategy.md#assumptions); показатели скорости и сообщений — в соответствующих контрактах.
