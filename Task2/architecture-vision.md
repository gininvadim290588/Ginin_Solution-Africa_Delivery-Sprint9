# Africa Delivery — Architecture Vision

**1.0; 05.10.2026; предложено на 12.10.** Ценность: доступная покупка, достоверная оплата/получение, расчёт продавцу и проверяемая экономика заказа. Выбор — **модульный монолит, национальные контуры данных, лицензированные PSP и партнёрская доставка**. [ADR-001](adr-001-architecture-style.md); А1, с.1–3; А7; Task1 Canvas 1–9.

## 1. Контекст и объём

NG/KE, 100 продавцов/5 000 SKU: каталог/остатки, регистрация покупателя, заказ с ПВЗ либо координатами/ориентиром, M-Pesa KE/Flutterwave NG, кабинет/статус, SMS/WhatsApp, отчёты CEO. Проверка продавца/товара, возврат, сверка и выдача обязательны; перенос бэк-офиса допускает простой экран/ручные действия, не отсутствие операций. Саморегистрация не отменяет KYC PSP (кейс; А1, с.3; А3, с.2; А4; А8).

Android/мобильный web: кэш и постепенные изображения; продавец передаёт товары через WhatsApp/оператора. Кэш даёт чтение; наличие/цена/оплата подтверждаются сервером. SMS-код работает без интернета при GSM; выдача требует защищённой проверки оператором. Полный offline-checkout/выдача без любой связи не обещаны (А2; А4; кейс).

**Вне MVP:** ZA/B2B, seller BI, кошелёк/BNPL, токены, AI/live-shopping, мгновенный автоматический возврат, видео ПВЗ, собственные склады/диспетчеризация, iOS/пять языков. EN — старт; остальные после локальной проверки. CEO исправляет обещания А2 (А1, с.3; А2; А4; А7).

## 2. Архитектура и ответственность

| Часть | Ответственность |
|---|---|
| Приложение / каталог | Покупка/статус; проверка товара/наличия |
| Заказы / расчёты | Резерв/транзакционный учёт; один продавец/валюта; подтверждение PSP/сверка |
| Доставка / выдача | Адаптер партнёра, ПВЗ/ориентир, статус, одноразовый код/журнал |
| Уведомления | Событие, повтор/лимит, исключения оператору |
| Управление / отчёты | Модерация/возвраты/сверка, агрегаты CEO |

Модули ядра и фоновый процесс, а не пять микросервисов. Go/PostgreSQL, контейнеры/Linux, HTTPS API/webhook, транзакционное сохранение событий, метрики/логи. Kafka/Istio/Oracle/Kubernetes — после триггера/расчёта. Состав из А8, переносимость из А5, стоимость/партнёрство из А3/А6.

[C4](Diagrams/c4-context.png) ; [Use Cases](Diagrams/use-cases.png). Внешние: M-Pesa, Flutterwave, Paystack, Sendbox, Sendy, WhatsApp Business API, SMS/USSD. Paystack вне MVP; Sendy — кандидат из кейса, доступность/API неизвестны. CEO проверяет перевозчика KE; резерв — ручное оформление доставки. Платформа ведёт учёт, PSP исполняет платёж, перевозчик доставляет. USSD статуса/выдачи — при доступном short code (А3, с.2; А5, с.2; А8; кейс).

## 3. Данные и качество

PII/транзакции/логи/копии размещаем по стране; центральные отчёты — разрешённые агрегаты. Экспорт блокируем до местного заключения как предосторожность. А3 — предварительное письмо: уточнить классы/хранение/подрядчиков/передачу NG/KE; POPIA при ZA. Рекламная база ждёт законного основания. Карточные реквизиты не храним; RBAC/MFA, шифрование/секреты, подпись PSP и журнал сверки — MVP (А3; А6; А7).

99,99%/RPO=0/без деградации А5 **не доказаны**. Предложение: 99,9% платформенных запросов, p95 API≤1 с, первый товар≤2 с на согласованной 3G-модели; потеря площадки RTO≤60/RPO≤15 мин. При разделении сети финансовое подтверждение ждёт согласованности, каталог может читать. Требуются исключение инвестора, законная резервная площадка/бюджет; иначе no-go. Внешний PSP и полный путь измеряем отдельно. Порог нагрузки не задан (А1; А2, с.3; А5; Task1, технический предел).

## 4. Экономика

[TCO](tco-model.xlsx): копии шаблона A/B/C; 41,3М заказов/5 лет; ФОТ включён. Полный TCO с PSP/резервом **$38,243/$39,763/$45,016 млн**; без PSP **$13,256/$14,776/$20,029 млн**. A: техника **$3 950/мес**, ошибка спроса **$26 550**, заказ **$19,28** при 2К/мес → **$1,12** в месяце 12, без разового запуска. Take rate/субсидии неизвестны: прибыльность не доказана. [Детали](options-comparison.md); А6.

A достигает $5К при 9К заказов/мес: нужен следующий бюджет. PSP 2,2% all-in — гипотеза договора; публичный Flutterwave KE — 2,9% до налогов (источник в сравнении, 05.10). Same-day payout требует договора/резерва ликвидности, отдельно от IT TCO (А1; А6; А7).

## 5. Дорожная карта / late binding

До **12.10** CEO/CTO предъявляют готовность/публикацию/команду; CFO — оферты, комиссию, счета с отсрочкой 45 дней/позиции >$500; инвестор — объём/SLO; CTO — программу CNCF. **14.10 go/no-go:** договоры/правовые потоки, покупка/возврат/выдача, повтор без дублей, сверка/восстановление/нагрузка. Greenfield 05.10 к **15.10 не успевает**; лист ожидания не MVP (А1–А3; А5–А7).

После **90 дней пилота** — business case стран/языков/B2B/видео, конверсия/доставка/комиссия/сверка. Выделять горячий модуль при нарушении p95 после настройки либо ≥2 команды теряют >20% времени на релиз; **$120К миграции** уже в TCO. Kubernetes/mesh при ≥10 процессов/≥2 SRE, Oracle после ограничения БД, active-active после сценария отказов/площадок/финансирования — отдельные ADR (А5; А6).

## 6. Риски / пробелы

Б заполнено в [FMEA](fmea.md): правовой допуск **RPN 280**, готовность **252**, повтор оплаты **180**. RPN>100 требует немедленной меры; остаточный риск — после проверки контроля.

| Недостаёт → блокирует | Владелец / метрика |
|---|---|
| RPS/отказ/SLO → мощность | CTO/инвестор до 12.10; p95/ошибки/потерянные записи |
| Оферты/settlement → выплаты | CFO/CEO до 12.10; $/мес, % GMV, задержка выплат |
| Классы/сроки данных → хранение | Юрист до live; 100% потоков с заключением |
| Готовность/перевозчик → дата | CEO/CTO до 12.10; сценарии/договоры |
